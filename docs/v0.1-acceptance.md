# v0.1 acceptance matrix

Status: implemented and locally accepted on 2026-08-24.

This matrix maps the v0.1 implementation brief to executable evidence. “Implemented” means the declared v0.1 model exists and is connected to the common physical state; it does not claim OEM correlation, crash-analysis suitability, or v1.0 cross-platform bit identity.

| Area | Status | Implementation and evidence |
|---|---|---|
| Rust, WASM, Chromium, headless | Implemented | One Rust plant builds as `rlib` and raw `cdylib`; headless CSV runner and WebGL2 Chromium demo consume the same `PhysicsWorld`. |
| 1000 Hz fixed timing | Implemented | Player/high-priority rigid body and plant run every 1 ms; test advances exactly 1,000 ticks per second. |
| Variable timestep | Implemented | Bounded explicit API rejects invalid/non-finite steps; stability scenario covers 5 ms engineering steps. |
| Render decoupling and interpolation | Implemented | Previous/current transforms are retained and nlerp/lerp interpolated without mutating authoritative state. |
| 6-DoF chassis | Implemented | Position, quaternion, linear/angular velocity, force/torque integration, mutable mass, CG and computed inertia tensor. |
| Physics LOD | Implemented | Automatic proximity LOD, benchmark-derived device ceiling, manual browser/application selection, 1000/250/100 Hz force evaluation, 50 ms force blending and 0.5 s fidelity transitions. |
| Tire model interface | Implemented | Replaceable `TireModel`; Magic Formula-family reference behind the interface. |

## Acceptance gate

Run:

```bash
./scripts/verify-v01.sh
```

The gate requires formatting, warning-free Clippy, all native tests, JavaScript syntax, release WASM compilation and a ten-vehicle WASM benchmark faster than real time. Chromium is additionally verified manually/headlessly because GitHub-hosted runners do not guarantee a browser/GPU configuration.

## Deliberate v0.1 approximations

- The reference tire is Magic Formula-family rather than a proprietary fitted parameter set.
- Suspension is spring/damper ray-based, not hard-point geometry.
- Body deformation changes a parameterized collision envelope rather than a finite-element mesh.
- Capsule/convex contacts target deterministic vehicle/environment collision, not general-purpose 3D stacking.
- Road water evolves locally; flow and drainage are deferred.
- No real-vehicle correlation claim is made without licensed measured data.

These are fidelity choices within v0.1, not separate “game physics” implementations. The same parameter/state semantics remain the extension foundation for v1.0.
